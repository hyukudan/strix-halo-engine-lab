# Standalone Q4_K gate/up A8G32 probe

This isolated, opt-in experiment quantizes one activation row. It changes numerical behavior and is not an exact replacement for the default expert projection. It is not connected to model execution, admission catalogs, sessions, or workspace publication. Existing runtime source and target configuration remain isolated. A compiled identity receipt for default runtime objects/kernels is still pending. With BUILD_TESTING enabled, the new host-only contract library and test do enter the default build; they add no GPU kernels.

## Contract and arithmetic

`moe_q4k_a8_contract.hpp` names the numerical policy. Admission requires explicit enablement and exact identity approval; one logical row; hidden width 256..2560 in multiples of 256; output rows 32..640 in multiples of 32; 1..512 experts; top-k 1..10; separate Q4_K type 12 gate/up; BF16 or FP32 activation input. All nine caller-owned views require exact byte lengths, 16-byte alignment and checked address ends. Writable views are disjoint from every other view; gate and up are disjoint. The API allocates nothing and retains no pointer. Read-only data must remain immutable, and mutable views/status require exclusive stream ownership until quiescence.

Per 32 activations, delta is max(abs(x))/127 rounded to binary32 nearest-even, or 1 for an all-zero group. Each code is nearest-even integer of the **binary32-rounded** quotient x/delta, then clamped to[-127,127]. Nonfinite input and underflow to zero delta reject the entire quantization before any external code/delta/sum or output is written. BF16 input expands exactly to FP32. Gradual FP32 subnormals are required, not silently ignored. A maximum of 64 minimum FP32 subnormals maps to 64, not127. A maximum of 63 underflows its delta and is rejected.

The first compile-only attempt called the declared `__ocml_div_rte_f32` directly, but the actual Core10.1 link could not resolve that hidden symbol. Probe v2 therefore uses source division with the explicit target option `-fhip-fp32-correctly-rounded-divide-sqrt` and gradual-denormal policy `-fdenormal-fp-math=ieee`. The compiler [documents the correctly rounded HIP division option](https://clang.llvm.org/docs/ClangCommandLineReference.html#cmdoption-clang-fhip-fp32-correctly-rounded-divide-sqrt). Fast math remains disabled, and `-ffp-contract=off` follows that option so a later fast-math reset cannot re-enable contraction. Actual linked device code, division IR attributes, FP modes and device division oracles must qualify this implementation. The unresolved early source/receipt remains separate historical evidence; it did not execute on a GPU.

For each Q4_K group, R = sum(q*a) and S = sum(a) are integer-exact. The combine is separate FP32 u=d*(s*R), v=dmin*(m*S), t=u-v, contribution=delta*t. Two consecutive groups are added, then accumulated in ascending256-element block order into four leaves. Only lane c0 stores ((leaf0+leaf1)+(leaf2+leaf3)). Finite-math/fast-math compiler modes are rejected at preprocessing. No FP contraction, weight conversion, activation fallback or precision mode is implicit. Eight native signed-activation/unsigned-weight dot4 operations process each lane's two16-element halves. There is no emulation fallback.

Projection equality is qualified only when the weight headers and **every** combine/accumulation intermediate are finite. `evaluate_row` executes this predicate and rejects unqualified cases. The GPU propagates exceptional arithmetic; fixtures record unqualified output bits and verify bounds/status, without asserting universal NaN payload or signed-zero commutativity. Half conversion covers all 65536 encodings: finite/Inf/signed-zero bits are exact-oracle gates; NaNs have classification-only scope.

## Status and lifetimes

The caller supplies a standalone sticky status word. Route bit 1, nonfinite activation bit 2 and invalid delta bit 4 are independent of existing graph/session statuses. The API never clears status. A stale HIP error rejects before the first enqueue. After an enqueue exception every writable view is indeterminate, even if status remains 0. Route validation precedes quantization; one 256-thread quantizer stages the whole row in LDS and publishes external workspace only after a CTA-wide error check. Projection follows on the same stream. Status and all other bindings must remain alive until the original device stream is known to have quiesced, including after a launch error. Enqueue success alone proves no completion.

Tests use `HipSetupQuiescenceGuard` to drain the original observed device before owner cleanup. This experiment does not implement session poison/publication contracts; integration must add them explicitly. It must never silently replace an exact path after a failed probe.

## Build and gates

The independent host contract/oracle test builds under ordinary BUILD_TESTING. `--exhaustive` additionally checks every 24-bit packed factor byte triple at all four offsets, both group branches. The independent quantizer oracle implements binary32 division using integer significands and RN ties-even before integer rounding. Executed negative controls distinguish direct-rational integer rounding, reciprocal-multiply division, activation threshold changes, packed factors, dmin removal, FMA contraction, reversed block order, nibble and half/pair mapping, swapped headers/factors, unsigned activation dots, a missing final tree step and a negative-zero leaf seed. A 1000-group boundary sweep covers wide activation exponents. Positive admission includes maxima and permitted read-only aliases; malformed dimensions must reject at their own dimension gate.

For a real HIP compiler, configure with `STRIX_ENABLE_HIP_RUNTIME=ON`, `STRIX_BUILD_EXPERIMENTAL_Q4K_A8_PROBE=ON`, gfx1151, strict warnings. First build targets `strix_q4k_a8_dot4_compile_probe`, `strix_q4k_a8_hip_probe`, and `strix-hip-q4k-a8-probe-tests`, but **do not execute** until linked gfx1151 object and ISA are reviewed. These are independent targets; no new TU or compiler option enters strix_hip_runtime.

Required linked-ISA gates are specific to each kernel. `project` must preserve separate affine subtraction, delta multiplication, leaf accumulation and final tree. The compiler may encode a single half-header times FP32 integer product with `v_fma_mix_f32` and a literal negative-zero addend: the half expands exactly, and under RN with gradual subnormals this equals the individual FP32 multiplication, including signed zero and underflow. This exception does not permit combining a nonzero addend or affine subtraction. Integer address MAD and separate VOPD add/multiply are also allowed. `quantize` has two source division sites and `division_receipt` has one: correctly rounded division lowering may use scaling, reciprocal seeds, FMA refinement and division fixup. Those internal fused operations are allowed; an unrefined reciprocal-multiply substituted for the observable quotient is not. Inspect both actual division sites and the receipt kernel, their strict `fdiv` IR without approximate-math flags/metadata, linked definitions, FP32/FP16 denormal and rounding modes, packed load byte ranges, signed dot4 flags, per-leaf order and writer tree. Validate bounded LDS/private/register resources and spills. Exact opcode counts are code-shape measurements, not a standalone proof of arithmetic correctness. The tiny compiler probe is only an initial gate, not evidence for the full projection kernels.

After that review, the standalone device fixture exercises signed-dot integer oracles, randomized and adversarial exact-division oracles, both input storage types, H = 256/512/2560, canonical 640 rows/top-k 10, zero/subnormal/FLT_MAX/NaN cases, full workspace/output guards, route/status/input failure publication, and three static graph replays with stream-ordered poison before each replay, followed by captured replay-time sticky-status and invalid-route rejection. Every qualified normal case must compare all outputs; exceptional cases have explicit count policies so a throwing oracle cannot silently skip the suite. Readback destinations remain alive through original-device error drains. Source tests do not claim actual GPU results before those receipts exist.

Full-model integration is a separate future change. Preserve default behavior independently, report this candidate's complete-logit divergence and quality on fixed held-out tasks, and require acceptable operator error/quality gates before performance comparisons. The old 554-array exact reference is not this candidate's success criterion. No speed improvement is claimed by this standalone probe.
