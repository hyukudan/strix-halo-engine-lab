# Experimental prefetch8 Q8 GDN input variant

`--prefetch-q8-gdn-input` requires `--virtual-q8-gdn-input` and is disabled by default. It selects a distinct experimental kernel only for Q8 input projections. The existing legacy and virtual-streaming kernels and their identities remain available unchanged.

One physical lane still owns eight virtual leaves. Q8 row widths are admitted only in multiples of 32. An eight-feature group beginning at `chunk + 8*lane` therefore lies wholly within one block and is either entirely valid or entirely absent. The new loop uses that single guard, reads the eight raw BF16 activations and signed codes before updating the leaves, and loads their common half scale once. It preserves the decode expression, ascending per-leaf feature order, fused-update source expression, reduction tree and BF16-in-FP32 epilogue.

No new scratch, LDS, state/status access, alignment promise, inline assembly, cross-chunk pipeline or quad-scale broadcast is introduced. Source launch bound remains 32; the composite GDN catalog retains maximum actual launch 256 and conservative LDS 16640 because its other stages are unchanged. Register pressure and compiler load scheduling must be established from the actual code object.

The candidate is subject to a compile-only acceptance gate before GPU execution: a distinct function, one per-chunk predicate, batched reads and one scale read, eight fused accumulators, preserved finite tree/RNE, zero group/private segments and spills, matching FP modes, and unchanged existing kernel instructions after verified pool relocations. If the compiler reserializes the reads, stop this experiment rather than claiming prefetch from source arrays.

Host geometry checks cover every aligned tail residue and the maximum aligned uint32 width. Device fixture source compares all four raw projections with an independent fused CPU oracle and compare complete arena/state/output bits among legacy, current streaming and prefetch paths. Captures distinguish the two 32-thread functions and retain every other function. Canonical sparse/F32 fallback 1e-7 WAR gates remain; dense scalar-libm matrix differences stay explicit diagnostics under the previously documented family scope. CLI, identity/dependency/bundle, poison, guarded tails and failure contracts remain required.

No speedup is claimed. Actual ISA, clean device tests, full 554-array fidelity, paired performance and supported compiler checks are required before qualification. Projection-only fixture source additionally covers finite signed-zero, subnormal and maximum half scales, extreme signed Q8 codes and BF16 signed-zero/subnormal activations. A width2560 decode-association case distinguishes the preserved expression from an underflowing reassociation after BF16 rounding. These device cases remain unqualified until actual execution; NaN/Inf scale/activation behavior is outside this experiment. Unchanged descriptor modes alone do not establish universal exceptional-value equivalence.

Local strict host validation passes 146 tests. The underflow control actually executes on the host and produces BF16-in-FP32 bits `0x00020000` versus zero for the reassociation mutant. Host validation does not compile HIP kernels, run the HIP CLI checks or establish GPU prefetch scheduling.
