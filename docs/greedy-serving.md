# Greedy serving

## Explicit shared-projection cohorts

`--serve-tensor-cohort-rows 2|4` optionally groups currently ready independent C1 targets, bounded by `--serve-concurrency`. It never waits for a full cohort. Only the three shared-Q8 projections use tensor rows; the rest retain their per-request R1 arithmetic and state. Unsupported member combinations use the scheduler's explicit R1 fallback. Default rows=1 retains independent workers.

The cohort staging payload is charged to the shared reservation before the cohort is constructed. Stream/event driver overhead remains in the explicitly supplied serving headroom. No request snapshot, cache or state is shared across sessions. Telemetry wrappers forward the request binding around actual cohort work; the cohort reports its own actual shared/fallback counters. Prepared mode validates retained metadata but cohort execution uses direct layer-major dispatch, not the prepared run hot path. These source candidates remain unqualified until final validation.

## Explicit known-input prefill chunks

`--serve-prefill-rows N` admits 2, 4, 8, or 16..2048 known input rows. Supply both positive `--serve-prefill-workspace-budget-bytes` and `--serve-prefill-host-metadata-budget-bytes`. This mode requires eager D1, the paired GDN wave8 input/output profile with prefetch input and virtual input/output, and baseline recurrent and QSA layouts. It rejects tensor cohorts and the serial-only serving prefix cache in this source increment. No flag is silently disabled; the normal serving route remains unchanged.

Each admitted request retains state-only and terminal-row native plans, one serialized arena, separate identity-bound D1 records, and a terminal GPU selector. The scheduler consumes full known chunks without waiting for unknown inputs; short suffixes and generated inputs use R1. The final known input still produces and validates its selection when zero new tokens are requested. Terminal finite/firstmax selection runs after native completion and before the chunk publishes position, generations or lineage. A selector failure poisons the session and drains its original device before owners can be released.

Plan metadata is prepared once. Workspace, two status records, the extra selector, known metadata copies and bounded runtime payload are charged before an accepted request factory allocates them. Declared payload plus explicit serving headroom is a reservation, not an RSS or physical-fit measurement; catalogs, allocator and driver overhead are not falsely presented as fully measured. With prepared eager enabled, R1 execution uses the prepared path; native chunks use their own validated plans. Receipts count completed native chunks and their actual dispatch results, separately from R1 tails. These source fixtures and paths have not been compiled, executed or qualified.
